# PISA Variable Curation

This folder contains the authoritative, designed schema files for curating and transforming PISA dataset variables over multiple years:
- `PISA_variable_curation_school.csv`
- `PISA_variable_curation_student.csv`

## Schema Specifications

The active curation matrices (`PISA_variable_curation_student.csv` and `PISA_variable_curation_school.csv`) use a long-format structure with the following standardized header columns:

| Column | Description | Example |
| --- | --- | --- |
| `year` | The study year (PISA cycle) the mapping applies to. | `2022` |
| `target_name` | The unified, generic variable name published in `learningtower`. | `mother_educ` |
| `source_col` | Original column name in the raw dataset (`.sav` or `.txt`). Can be empty/NA if absent. | `ST005Q01JA` |
| `transformation` | R function from `transformation_registry` (in `Code/process_pisa.R`) applied to decode or coerce values. | `isced3a1` |
| `na_values` | Semicolon-separated raw codes representing missing `NA` values. | `9997;9999` |
| `description` | Human-readable note or label describing the variable. | `Mother <Highest Schooling>` |
| `type` | Target R data type (`character`, `factor`, `numeric`, `integer`) asserted upon extraction. | `factor` |
| `note` | Additional contextual notes or extraction anomalies. | `encoded as binary` |

### Primary Key Constraints

The pipeline enforces strict primary key non-nullness and uniqueness checks via `transform_pisa_variables()`:
- **Student Data Primary Key:** `country`, `school_id`, `student_id`
- **School Data Primary Key:** `country`, `school_id`

None of these primary key identifiers may contain `NA` values.

## Purpose
These curation matrices are highly effective at providing a unified, standardized schema mapping for variables across all PISA years. They dictate how raw column names and formats from various years map to our unified `learningtower` dataset structure.

## Ensuring Reproducibility
These curation matrices are the central nervous system of our data harmonization. By completely eliminating hard-coded variable mappings and `NA` handling from deep within individual R scripts, we establish a single, auditable source of truth. Any researcher can look at these CSVs and instantly trace exactly how a variable from 2000 logically maps to a variable in 2022. This transparency is the cornerstone of absolute reproducibility in our dataset generation.

## Maintaining Consistency with Original Codebooks
A critical requirement for these curation files is that they must remain strictly consistent with the original PISA codebooks (e.g., `2000student.pdf`, `2003school.pdf`). These original codebook PDFs dictate the underlying variable names, fixed-width positions, value labels, and descriptions as officially released by PISA.

However, extracting precise schema details and mappings directly from legacy PDF codebooks is notoriously difficult for automated tools in R or Python because of inconsistencies in formatting and unstructured layouts.

## Automated Extraction Pipeline
To bridge the gap between unstructured PDF codebooks and our highly structured `.csv` schema files, we designed a dedicated extraction utility located in the `codebook` directory:
- `codebook/extract_codebook.py`

This Python script leverages AI-based document parsing (via LlamaExtract) to systematically read the raw PDF codebooks and transform them into highly structured JSON files. 

When updating or extending the variable curation CSV files in this folder, always refer to the extracted JSON outputs generated by `extract_codebook.py` to ensure all variable identifiers, descriptions, and technical specifications perfectly align with the original source material.

## Validation Script
To ensure that the manually curated CSV mappings are completely accurate and free of typos, we provide a validation script (`validate_curation.py`) located in the `codebook` directory. This script cross-references the curated CSV file against the extracted JSON codebooks.

### Checks Performed
1. **Variable Existence**: Verifies that every raw variable listed in the `source_col` of the CSV exists in the extracted JSON codebook (case-insensitive).
2. **NA Value Coding**: Ensures that all missing values listed in the `na_values` column of the CSV correspond to valid `key` entries in the JSON codebook's `variable_key_value` mapping.

### Usage
Run the validation script from the `codebook` folder using the central YAML manifest:
```bash
cd ../codebook
python validate_curation.py --tasks extraction_tasks.yaml
```
